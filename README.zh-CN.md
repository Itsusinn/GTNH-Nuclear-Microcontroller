# 强冷核电OC自动化

此方案在低tps环境能正常运行，允许在运行时重启游戏服务端。

此方案没有摆放限制，提及的容器与微控制器相邻即可。

**支持的燃料棒**：四联钍、四联铀、四联浓缩铀、四联MOX、四联浓缩钚、四联超能硅岩、“核心”、四联泰伯利亚、四联激发铀、四联激发钚

- 支持混合棒：“核心” + 激发铀、 “核心” + 激发钚

**支持的冷却单元**：3种氦冷、3种钠钾、4种空间、中子热容

**限制**：

- 仅支持六仓强冷构型（缺少反应仓会报错）

- 只能使用一种燃料棒与一种冷却单元（或上述混合棒），否则报错

- 冷却单元每秒耐久消耗不得超过10%（产热与热容不匹配会报错）

- 使用MOX燃料棒时需要手动升温

## 配置

- 将`nuclear.lua`内的代码保存到OC电脑的文件中。

- 给OC电脑换上空的EEPROM，执行`flash <文件名>`，按照指引将代码烧录到EEPROM中。

- 在电子装配器中按顺序放入：T1微控制器外壳、转运器、T1红石卡、T1中央处理器(CPU)、T1内存、以及烧录过的EEPROM，然后点击组装。

备注：EEPROM的存储空间为4KB，源码文件(`nuclear_SourceCode.lua`)过大，务必使用通过重命名变量等方法压缩过的代码(`nuclear.lua`)。

## 使用

- 微控制器需要供能（可以通过ME接口供能）。

- 若检测到非预期的情况，程序会停止反应堆调度，先持续报警 8 秒游戏时间，再将原始错误交给 OC 并退出，正面指示灯闪烁红光。报警完成后可用分析器读取原始错误；若提前断电或手动关机，则不会执行到报错步骤。修复故障后需要手动重启，报警期间撤掉或恢复红石控制信号都不会恢复运行或改变报警时长。

- 故障时会先关闭所有反应堆，再向已确认没有反应堆的方向持续保持强度 15 的红石信号，可直接激活相邻的 IC2 Nuclear Control 蜂鸣报警器，或通过独立红石线路连接报警器。报警期间每隔 1 秒游戏时间重申输出，不在两次写入之间清零；红石组件暂时故障后也会重试。8 秒到期时关闭全部输出，再报错退出；报警操作失败不覆盖原始错误。重启程序也会清除报警输出。正常撤掉控制信号停机、换料及重试期间不输出此报警信号。

- 建议将报警器放在微控制器上方或下方，且该方向没有反应堆。水平朝向未识别时，故障处理只启用安全的垂直方向；水平报警器还可能被首次朝向探测的红石脉冲短暂触发。报警线路不要连接反应堆或其它需要独立控制的设备，因为故障时所有已确认的非反应堆方向都会输出信号。

- 报警依赖微控制器供电及红石组件正常工作；断电、红石组件故障，或尚未完成容器扫描时发生组件故障，无法保证报警。扫描未完成时只尝试关闭全部输出。

- 换料时遇到输出空间不足（包括 ME 接口已满）或可用冷却单元不足，会在首次失败后每隔 1 秒游戏时间重试一次，最多重试 3 次。等待期间对应反应堆保持关闭；第三次重试仍失败则持续报警 8 秒游戏时间后报错退出，重试期间恢复成功则会再次检查才允许启动反应堆。

- 程序运行期间不会自动启动核反应堆，给予微控制器任意强度的红石信号即可启动。

- 运行中撤掉红石控制信号后，继续运行 10 秒游戏时间再停机；期间恢复信号会取消停机，再次撤掉信号时重新计时。倒计时期间仍正常检查和换料，换料所需的停机不受此延迟影响。

- 红石控制信号**不要**传递给反应堆，反应堆的启停应留给微控制器控制。

- 一个微控制器可控制多个反应堆，但**不要**让微控制器同时接触同一反应堆的两个面。

- 微控制器需要紧贴核反应仓放置，支持以下两套使用方法。

**1. 普通容器模式**

- 启动期间搜寻附近容器，若无ME接口自动进入此模式，搜寻只会在启动时执行一次

- 会将包含燃料棒或耐久在30以上的冷却单元的方向标记为输入方向（可以有多个）

- 会将不包含燃料棒与耐久在30以上的冷却单元的一个容器方向标记为输出方向

**2. ME模式**

- 启动期间搜寻附近容器，若存在ME接口或ME二合一接口自动进入此模式，搜寻只会在启动时执行一次

- 燃料棒与冷却单元的输入输出均通过此ME接口进行


# 代码压缩过程

使用 Cargo 单文件脚本，无需 Python、Node.js 或全局安装 `luamin`：

```sh
rustup toolchain install nightly
cargo +nightly -Zscript compress.rs
```

Rust 依赖和版本写在 `compress.rs` 内，首次执行时由 Cargo 下载并编译，后续执行复用缓存。
默认路径相对于脚本目录；可用 `--source <路径>`、`--output <路径>` 指定输入输出。
执行 `cargo +nightly -Zscript compress.rs --check` 可以检查固件是否最新，不写入文件。

构建先用 Lua 5.2 编译器检查源码，再通过 `luck_minifier` 缩短局部变量并移除注释与多余空白；
保持全局名称、数值字面量和计算流程，不进行常量折叠或内联。
随后自动选择重复文本建立字典，使用源码中不存在的可打印字符作为标记，并在单次 `gsub` 中解码。
字符串会自动选择较短的安全引号或长括号形式，不再限制源码使用旧的保留字符。

构建会验证解码结果与压缩前文本逐字节一致、检查生成代码的 Lua 5.2 语法，
并按 UTF-8 字节数检查 4096 字节的 EEPROM 容量。全部通过后才原子替换 `nuclear.lua`，失败时保留旧固件。

组件模拟与压缩回归测试：

```sh
cargo +nightly -Zscript test --manifest-path compress.rs
python -m pip install -r requirements-dev.txt
python -m unittest discover -s tests
```

模拟会在 Lua 5.2、5.3 和 5.4 中运行源码及 EEPROM 代码，不能代替游戏内实测。
